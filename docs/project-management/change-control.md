# Change Control

1. Log the requested change with business reason.
2. Assess scope, schedule, cost, architecture, security, data and operational impact.
3. Identify affected requirements and acceptance criteria.
4. Obtain product/sponsor approval for material changes.
5. Update roadmap, risks, architecture decisions and implementation tasks.
6. Implement through review and CI.
7. Validate acceptance criteria and close the change record.

Emergency security/reliability changes may use an expedited path but must receive retrospective review.
