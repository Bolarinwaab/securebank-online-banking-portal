# Change Control

1. Requester documents change, reason and desired outcome.
2. PM records scope, schedule, cost, risk, security and architecture impact.
3. Technical leads assess feasibility and dependencies.
4. Security reviews control/compliance impact where applicable.
5. Approver accepts, rejects or requests revision.
6. Approved change enters backlog/release plan with acceptance criteria.
7. Implementation is tested and evidence is attached.
8. PM closes the request after acceptance.

Emergency changes require incident authority, minimum safe controls and retrospective review.
